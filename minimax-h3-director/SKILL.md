# 海螺 H3 导演 · MiniMax H3 Video Director

把用户的一句话需求、大概故事、或资产参考图，转成一段**丢进去就能稳定生成**的 MiniMax H3 视频提示词。

核心判断：H3 不是"你说什么它画什么"的画板，而是一个**听指令干活的剧组**——你得告诉它拍什么镜头、镜头怎么动、谁在说话、现场什么声音、配什么乐。指令越精确，出片越稳。所谓"绝对能生成"，就是同时满足两层：

- **工程层（H3 官方规范）** → 保证模型"听得懂、不跑偏、能吐片"。
- **导演层（内置电影知识库）** → 保证画面"可信、有电影感、不像 AI"。

只做工程层会得到平庸素材，只做导演层会得到跑偏的"艺术照"。两者必须同时命中。

---

## Workflow（固定顺序，勿跳步）

0. **前置资产规划（可选但常被跳过，别跳）**：判断用户是否需要参考图。已有资产 → 直接进 1；没有 → 先产出**资产清单 + 生图提示词**（场景图·正常底 / 物品图·白底 / 发光元素图·黑底），每张注明 H3 用途（首帧 / 场景锁 / 身份锁）与画幅一致性（首帧画幅=成片画幅）。**生图提示词一律路由到 zy-cinematic-realism：先调用 Skill 工具加载 zy-cinematic-realism（`~/.workbuddy/skills/zy-cinematic-realism/SKILL.md`），按其工作流产出每张资产的生图提示词（电影写实单帧：动机光、物理场景、去 AI 感）；本 skill 不自行写生图提示词**，只负责视频提示词与资产用途/画幅规划。详见 `references/multi-segment-workflow.md`。
1. **判任务类型**（路由，决定模板骨架）。
2. **锁定用户硬事实**：人物/时代/地点/事件/情绪/天气/画幅/时长/是否要声音。缺失项用克制默认值补齐，只有会实质改变结果时才问一句。
3. **找情感主体**：字面主体之下真正想表达的情绪是什么？这句前一刻发生了什么、下一秒会怎样？
4. **选具体故事节拍**：优先"等待、余波、离别、私下观察、被打断的日常"，而非英雄高潮（用户点名高潮除外）。
5. **给角色一个具体小动作**：用姿态、距离、凝视、把玩物件、沉默来表达情绪，不要让角色对着镜头摆拍。
6. **搭物理可信的场景**：前景/中景/背景、年代、天气或空气、磨损、2-4 个与故事相关的使用痕迹。
7. **把相机放到真实能放的位置**：高度、距离或景别，只在有用时给焦距，必要时给一处遮挡/反射/空间边界。
8. **动机光**：每一个重要光源都要有场景来源。写主光源、次光源、阴影、高光、克制的色彩关系。
9. **写分镜与运镜**（工程层核心）：按时间轴切镜，每镜一个运镜（类型+幅度+速度），写成自然的动作句而非句尾标签。
10. **写声音层**：Sound（音效绑动作+环境声叠）+ Music（乐器/速度/动态，或 N/A）。
11. **加捕捉质感最后**：自然曝光、高光滚降、可信颗粒、克制 halation、镜头衰减、焦点瑕疵、运动模糊——只用场景支持的。
12. **过质检**（见下方硬规则 + quality-checklist），删占位符。
13. **看片诊断**：生成后逐镜回看，对照 `references/h3-failure-diagnostics.md` 的翻车清单（手脸漂移/文字错乱/运动伪影/音画不同步/嗡嗡声/身份跳变），定位出问题的 Shot。
14. **定向修正**：单点问题用 H3 指令式编辑（把出片作为 `@video1` 提交，只列"目标→结果"的修改项，保留其余不变）；系统性问题（光/色/构图/节奏）则重写该段时间轴重生成。
15. **再校验**：修正后重生成，确认问题 Shot 已解决且未引入新漂移，再交付。

## 第一步：任务类型路由（先问：用户给了图吗？给几张？首帧还是尾帧？）

| 类型 | 参考图 | 用户角色 | 提示词重心 |
|---|---|---|---|
| **T2VA** 文生视频 | 无 | 从零编剧 | 完整建立整个视听场景 |
| **I2VA** 图生视频 | 1 张（首帧） | 接着图往后拍 | **只写"变化"**：动作、运镜、声音；不重述图里已有的外观/服装/环境 |
| **FL2VA** 首尾帧 | 2 张（首+尾） | 编排中间过渡 | 描述首尾之间的运动/变换 |
| **L2VA** 尾帧 | 1 张（尾帧） | 反推前情 | 描述如何自然抵达该尾帧 |
| **Ref2VA** 参考生视频 | 参考图锁角色/风格/动作/运镜 | 换场景复用资产 | 用参考的"身份/风格/动作"拍新场景 |

**关键差异**：选错类型是"一脸懵"的头号原因。I2VA/FL2VA/L2VA 里图片已经承载外观，**文字要全部用来买"变化"**——重复描述起始帧已呈现的内容是浪费提示词的最常见方式。

## 第二步：三段式组装（官方公式）

官方把完整提示词定义为三段，按序写：

1. **参考素材说明**（有图才写）：每个文件按 `@image1 / @video1 / @audio1` 编号，就地声明一个"角色"。没传文件就跳过。
2. **核心创意**：主体 + 地点 + 事件 + 视觉风格 + 一句话概括整段。
3. **分段过程描述**：按时间顺序描述动作，带时间戳（0–4s、4–8s…）。15 秒的视频尤其需要节拍，否则动作会被挤在前几秒。

> 提示词上限约 7000 字符，官方示例往往用满大半篇幅。写不满不是问题，**把所有内容糊成一段不分层的文字才是手册列在第一位的失败模式**。

## 第三步：导演层（内置完整电影知识库）

本 skill 内置 zy-cinematic-realism 的完整电影知识体系，自包含运行。构建画面时按需查阅以下内置文件（见 [Reference Routing](#reference-routing-内置文件导航)）：

- **叙事与构图** → `references/cinematic-principles.md`
- **相机与光** → `references/camera-and-light.md`
- **负面提示词** → `references/negative-prompts.md`
- **去 AI 感清理** → `references/anti-ai-cleanup.md`（每次输出前必读的全局清理层）
- **导演四轴路由** → `references/director-routing.md`
- **47 位导演库** → `references/directors/index.md`（中文/日/韩/欧美作者电影全覆盖）
- **导演推荐矩阵** → `references/directors/recommendation-matrix.md`
- **成片示例** → `references/examples.md`
- **质检清单** → `references/quality-checklist.md`

核心导演原则（内联速记）：

- **叙事优先**：先定"故事节拍"再定镜头，让画面像"被拍进正在进行的故事里"。
- **情感主体**：字面主体之下的情绪才是重点；情绪用姿态/距离/凝视/沉默表达，不摆拍。
- **相机决策顺序**：① 相机能站哪 → ② 距离（大全景/全景/中景/近景/特写）→ ③ 高度与角度（平视/坐姿平视/腰高/地面/俯仰）→ ④ 边界（门框/座椅/玻璃/车流/窗帘/无遮挡）→ ⑤ 焦距行为（开阔/中性/压缩/亲密）→ ⑥ 运动（锁定/克制手持/车载震动/缓慢漂移/静止）。
- **焦距参考**：24-32mm 空间与邻近感；35-50mm 自然观察；65-85mm 压缩隔离；100mm+ 远距离压缩。不要用镜头选择替代相机位置。
- **动机光**：老绿荧光车灯+间歇琥珀街灯；阴天窗光+一盏低暖台灯；蓝调黎明环境光+墙面弱暖光；钠灯+便利店漏出的冷光；实用台灯+走廊微光。每个光源要有来源。
- **观察式构图**：偏离中心、负空间、部分遮挡、非对称、环境尺度——只在服务故事时用，不默认对称/居中/广告式。
- **捕捉质感**：自然曝光、软高光滚降、可信颗粒、克制 halation、镜头衰减、焦点瑕疵、运动模糊——作为"捕捉行为"而非装饰叠加。
- **去 AI 感**：表面不能蜡质/塑料，不能让每个物体同等清晰，阴影与衰减保留自然的"死区"，磨损要像住出来的而非设计出来的。

### 导演四轴检查（Director Four-Axis）

**两层优先级裁决**：当 zy 的"克制静态 / 观察式静止"与 H3 的"运镜推进 / 动作叙事"冲突时，**默认听工程层（H3 要运动）**——导演层只管光/色/构图/质感的统一，不强制 static shot；zy 的"观察式静止"降级为可选风格，非默认。

用户点名导演时，把该导演的四轴翻译成当前场景的具体决策（缺任一轴 = 失败输出）：

1. **光与对比** — 动机光层级、阴影分布、高光行为、对比形状、刻意保留的不可读暗部。
2. **色与曝光** — 光源决定的色彩关系、饱和度成因、肤色反应、黑白灰行为、允许的偏色或曝光漂移。
3. **镜头与相机** — 物理见证位置、观察距离、镜头行为、高度、对焦/景深策略、静止或运动的条件。
4. **构图与空间逻辑** — 视觉中心、主体尺度、负空间、遮挡、建筑、调度、信息层级、被隐藏的信息。

**强导演模式（Mandatory Strong）**：凡点名内置导演库中的导演，一律以最强 `iconic`（公开标注「强烈」）执行；`轻微/明确/强烈/subtle/clear/strong/iconic` 全部视为同一最强行为，不得降级。相对无导演基线，至少在三条轴上做结构性改变（换导演名/片名/焦距数字/浅景深/冷暖/颗粒/氛围词/裁切都不算结构改变），并重新选择至少 3/5 个观看决策（动作前中后时刻、主视觉中心、相机见证位置、主体尺度与完整性、环境/人/物谁主导画面）。

导演签名块（插在场景事实之后、细化镜头设计之前，五行连续不断开）：

```text
Director and visual reference: [标准英文导演名], drawing strongly from the visual language associated with [代表影片1], [代表影片2], and [代表影片3].

Lighting and contrast signature: [当前场景决策].
Color and exposure signature: [当前场景决策].
Lens and camera signature: [当前场景决策].
Composition and spatial signature: [当前场景决策].
```

名字与片名是模型信号，不是替代品。保留用户的角色/事件/时代/地点，除非用户明确要求复刻某电影场景。不用 `in the style of` / `directed by` 空话。仅当用户明确要求匿名提示词或平台不允许导演名时，才省略名字与片名，但仍保留四轴签名与最强内部语法。

### 多镜头导演贯穿

点名导演时，四轴签名块（Director Signature Block）只在 **Shot 1** 写一次，建立该导演的视觉语法基线。Shot 2+ 不重写整块，而是用一句"继承 / 演进"标注维持连贯：

- 继承句例：`Continues the Wong Kar-wai neon color and compressed proximity from Shot 1.`
- 演进句例：`Cold shift from Shot 1's warm tone — the neon now reads as departure, not romance.`

原则：跨镜保持**色彩关系、光源层级、镜头距离逻辑**三条不变；只在叙事需要时让某一轴演进（如情绪转冷、机位拉远），且演进要写清原因（"as the argument ends"）。不要让每个镜头各自重新定义导演风格，否则会逐个镜头风格跳变。

## 第四步：声音层（H3 最独家能力，必须写）

原生音频与画面同一次生成，32kHz 立体声，台词口型天然同步。**你不写，模型也会出声，只是出的不是你要的声音。** 写完画面后以 `Sound:` 收尾。

- **音效必须绑在可见动作上**："软木塞飞出瞬间一声轻响"能对齐；"一声轻响"会漂。
- **环境声随便叠**：雨声、人声嘈杂、音乐可共享一个声床，叠几层环境声给镜头"地点感"。
- **音乐按风格下 brief**：写曲风/速度/情绪/配器，需要画面主导时加"无人声"。永远不点名某首歌/艺人。
- **不要背景音乐必须明说**：`non_diegetic_music: N/A`（或 Music: None）。否定诉求不写出来几乎一定被忽略。
- **无音乐 / 后期配乐模式**：用户后期自己配乐时，声音层只写**环境声 + 物理音效**（琴键/碰撞/落物/气流声——同时是后期配乐的"节拍器"），负面清单写死"无任何音乐、旋律、配乐、人声哼唱"。注意 `non_diegetic_music: N/A` 只管背景乐，画面内 diegetic 旋律（如钢琴声）仍会被生成，必须显式禁掉。交付附**配乐对齐点表**（关键动作的胶片时间）。详见 `references/multi-segment-workflow.md`。
- **台词口型**：台词放引号里，逐字写出，加 `[语言]` 标签（中/英/日/韩/法/德/意/西/葡/俄/阿 11 种原生支持）；说话人给稳定 ID `(S1)/(S2)`，音色写在标签外；旁白必须紧跟"画面里嘴唇没动"。台词长度要配时长，5 秒镜头配一两句。

## 第五步：硬规则清单（"绝对能生成"的工程底座）

**时间戳与分镜**
- **标准写法（主推）**：后续每个镜头以 `At 00:0X.000, the camera cuts to ...` 开头（毫秒级绝对切点，官方 guide 规范写法，最严谨、连续无重叠最易保证）。首镜不带时间戳。
- **简化写法（允许）**：短视频简单分段可用 `[0-4s] / [4-8s] / [8-15s]` 区间标注（官方示例亦可见 `[2s-4s]`），但必须顺序连续、无 gap、无 overlap，且末区间结束于总时长。**推荐优先用精确切点**。
- 每镜 **2–5 秒**；低于 1.5 秒模型没有足够帧数。
- 镜头预算：4-6s → 1-2 镜；7-10s → 2-3 镜；11-15s → 3-5 镜（最多可到 6 镜快速蒙太奇，但须每段明确一个景别与镜头任务）。短视频塞太多镜=混乱。

**镜头运动**
- **一镜一运镜**。`Slow dolly in with orbit and crane up` 会混淆模型，需要多个运镜就拆到不同镜头。
- 完整运镜 = **类型 + 幅度 + 速度**（幅度/速度在中等时可省略）。写进动作句中间，别堆句尾当标签。中文词：小幅/大幅、慢速/快速（如"缓慢推近""快速横移"），中英可混用。
- 高可靠运镜：slow dolly in/out、tracking shot、crane up/down、static shot、pan left/right、zoom in/out、push in/pull out、POV、handheld。**orbit 不推荐单写**（实测不稳，用 `truck + pan` 组合代替，见 h3-engineering-rules.md）。
- 切镜后**指明新镜景别**，是保持人脸一致的关键。单个镜头内不要叠加多条运镜指令。

**风格**
- **只选一个风格并坚持**：Cinematic / live-action / 2D-animated / 3D CG / claymation / watercolor / vintage film / anime / cyberpunk / film noir / documentary / black and white / retro VHS / steampunk / 国风 3D / MG 动画 / 二次元赛璐璐。不要"photorealistic anime"这种混搭；写实优先 live-action / cinematic。

**禁用项（写了反而更糟）**
- 元指令：`8K` `4K` `masterpiece` `highly detailed` `award-winning` `viral` `trending` `cinematic masterpiece`。
- 转场语言：`dissolve to` `smooth transition`、`fade to black` 收尾（H3 默认自动切镜，直接结束一镜开始下一镜；**镜头间叠化转场 `fade` 是允许的**，不要和"fade to black 黑场收尾"混淆；仅当用户明确要求黑场收尾时保留 fade to black）。
- 文字/Logo/字幕：**默认不要**画面内文字（H3 出片默认干净）；**但 H3 官方支持文字渲染**——若用户明确要求文字/Logo/标题/标语，必须**把文字原文逐字写出**（如 `手机屏幕显示标题："AI Video Creation"`），不要用"一些文字"模糊带过；遇到文字乱码，可把文字做成**图片参考**并在提示词声明"这张内容必须按图片理解，不能按文字处理"。不要用"请求渲染文字不可靠"一刀切禁止用户要的文字。
- 指定 FPS 或帧数（用时间戳控时长，不写"24fps"）。
- 幻灯片式："Show A. Then show B. Then show C." → 写成连续运动。
- 图生视频里重述首帧外观（图已承载，写"变化"）。

**提示词写作原则（H3 实测）**
- **少用比喻，多写可见画面**：H3 更擅长理解明确的画面指令（景别、动作、光、物体），不是抽象比喻。把"像被雨声洗过的记忆""时间膨胀"这类比喻改写成可见描述（表盘滴答、雨滴在玻璃上缓慢停滞、瞳孔里流动的光）。比喻只可放在核心创意的一句话概括里，画面过程段一律写看得见的东西。
- **切镜风格四选一**（写进核心创意）：普通硬切 `cut`、镜头间叠化 `fade`、跟随节奏卡点切、快切 `fast cut`；默认硬切，H3 自动处理切点。

**画幅与时长**
- 支持画幅（文生视频 / 全能参考模式）：`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16`；首尾帧模式遵循原图比例。先选对画幅再雕琢光影：Reels/TikTok/视频号 → 9:16；方形头像/产品 → 1:1；复古/剧集 → 4:3；YouTube/网页 Hero → 16:9；电影预告 → 21:9。
- 分辨率两档（生成时选）：`768p`（短边 768，轻量、快、可后续升级）/ `1440p`（官方推荐，短边 1440；21:9 时 ≈ 2976×1248）。默认给 1440p，移动端快速验证可用 768p。
- 时长甜蜜点：4-5s 单镜头快速时刻；6-8s 迷你故事；9-12s 完整场景；13-15s 延长序列。
- 图生视频/首尾帧由输入图片决定画幅，不再另设 aspect_ratio。

**参考素材（12 种角色，声明用途是硬要求）**
- 角色参考/物体参考/场景参考/关键帧（必须明说首帧还是尾帧）/声音参考/分镜稿/风格参考/构图参考/音频复用/音频部分复用/动作参考/运镜参考/视频编辑。
- **上传了参考文件却没写明用途 = 参考被无视的头号原因**，不要让模型自己猜。
- **参考图只挂"本段画面里实际出现的元素"**：不要提前挂下一段才登场的元素（如第二段才出现的道具/角色），H3 会在本段尝试"用掉"它，破坏出场节奏；首次登场的元素，在它出场的那一段用参考图锁定即可。
- **白底/黑底物品参考的底色泄漏**：物体参考用白/黑底（干净抠图）时，提示词写明"只取物体身份、忽略背景"，负面清单加"不要白/黑背景色块"，防止白底染进夜景等场景色调。

**跨段拼接衔接（多段独立生成拼长片，如 15s+15s 拼 30s）**
- H3 单次上限 15s，长片须拆段独立生成再剪辑拼接。两段之间**没有模型级一致性**——按下面四层手段从强到弱组合使用，目标是切点两侧"方向一致、不南辕北辙"。**注意：尾帧续接（第 1 层）仅在用户明确要求时使用，默认不主动用，默认路径为第 2 层文字设计。**
- **第 1 层 · 尾帧续接（可选增强，仅用户明确要求时用；默认不主动用）**：H3 支持参考上一段生成的**真实输出**。Clip1 生成后导出其**最后一帧**（单图，最轻量、比例跟随原图）或**整段视频**（可继承运动/光，总时长 ≤15s），作为 Clip2 的参考素材上传，并声明用途："上一段结尾帧——本段从这一帧的画面继续，构图、机位、光线、主体位置与之一致，仅在此基础上发生以下变化…"。Clip2 的提示词**只写变化**（动作/运镜/声音），不要重述帧里已有的外观（I2VA 原则）。两段运镜方向相反（推近→后拉）时，尾帧续接让切点变成"同一位置换运镜"，连贯性最好。
- **第 2 层 · 文字设计（无尾帧可传时）**：禁止"同帧镜像"（本段结尾=下段开头、同一景别同一构图——两段独立生成不可能像素对齐，同构图硬切像卡顿/倒放）。正确三件套：① **景别不同**——前段收近景、后段起中景（更远/不同重新取景），景别变化是标准剪辑语法；② **动作匹配**——切点两侧同一动态主体（粒子/灰尘/水流/运动物体）保持同一运动方向，动态能盖住两段差异；③ **共享场景锁**——两段挂同一张场景参考图锁场景/光线/主体。
- **第 3 层 · 机位与空间词统一**：两段"运镜"行写明同一机位高度/角度（如"全程保持观众席前排低角度"）与同一空间语言（如"向舞台上空聚拢"），减少生成漂移。
- **第 4 层 · 剪辑兜底（保底）**：生成后验收三点——切点方向一致、关键动作一眼可读、色调统一（色轮微调）；残差用 2–4 帧叠化或错位 2–3 帧（J-cut）掩盖。
- **结尾别"停住"**：前段在动势中收尾（运动没停），切点即"正在发生的瞬间"；静止收尾会放大两段差异。
- **高潮/转折/结局留足时间**：别把"转折+散场+收尾"塞进最后 2–3 秒，H3 会压缩到看不清；给关键动作 4 秒以上的独立时间窗。
- **每段参考图组合模板**：每段开列"挂图清单 = 尾帧续接/首帧 + 场景锁 + 本段出现元素锁"，跨段只共享场景锁；每张图注明用途（详见 `references/multi-segment-workflow.md`）。
- **降级路径**：单段内动作过多翻车 → 降级为更多短镜（2×15s → 5×6s）：每镜一动作更稳，切点变多但景别跨度大更能掩错；短镜同样适用尾帧续接（每镜用上一镜尾帧续）。

## Output Contract（输出顺序）

1. `画面理解` — 一句中文概括故事节拍与关键制作选择（用户用中文时）。
2. `Final Prompt` — 一段完整、连贯、可直接粘贴的**中英双语**提示词：先用英文写完整 prompt（海螺 App/ComfyUI 直接粘贴），其后附**一整段中文翻译**供阅读理解，不逐行交错。海螺 H3 原生中文优化与英文同级，双语双保险覆盖两种解析路径。
3. `参数` — 一行注明：任务类型 / 画幅 / 时长（用户不指定时给推荐值）。

规则：
- 不暴露隐藏推理，不留占位符，不把用户 brief 逐字复述当成品。
- 用户只要素材 prompt 时，省略"画面理解"，直接给 `Final Prompt` + `参数`。
- 用户点名导演时，在画面描述中插入导演四轴签名块（见第三步），但不写"in the style of"空话。
- 默认输出**中英双语**：英文完整 prompt 在前、整段中文翻译在后（不逐行交错），两段都可直接粘贴给 H3，双保险覆盖中英文解析路径；写法见 `assets/prompt-template.md` 的「双语写法」段。**中文用户默认直接给中文主版**（H3 原生中文优化，可直接粘贴）；用户明确要双语 / 纯英文 / API 三字段时再切换：API 三字段用 `integrated_multimodal_description / overall_soundscape / non_diegetic_music`。
- 双语（英+中两段）约使提示词长度翻倍，注意 7000 字符上限：复杂多镜（≥5 镜）优先保证英文 prompt 完整，中文翻译段可适度精简（保留风格 / 关键动作 / 声音），勿溢出截断。
- 负面提示词按适配层处理：**不输出独立 `Avoid` 字段**，在正文末尾用一个明确的 `Negative list:` block 集中写 **3–5 条最关键拒绝项**（默认：无人 / 无文字水印字幕 / 无音乐 / 无快切 / 无电流底噪），场景特定项最多再加 2–3 条，**总长 ≤8 条**（过长稀释权重）；其余瑕疵用正面质感描述替代。**例外**：若用户明确要求画面内文字/Logo，则不写"不要文字"，改为在正文写出文字原文（见第五步禁用项说明），并在 Negative list 仍保留"不要背景音乐"等其余项。
- 完成前过一遍 `references/quality-checklist.md`、`references/anti-ai-cleanup.md` 与 `references/zy-to-h3-adaptation.md`，弱段重写后再回答。
